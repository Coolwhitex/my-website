Spark 性能调优指南

一、内存与资源调优

Executor 内存分执行内存与存储内存，默认各占一半。根据作业特性调整 spark.memory.fraction 与 spark.memory.storageFraction；合理设置 Executor 数量与核数，避免资源浪费或过度竞争；注意 JVM 堆外内存与 Overhead 配置。

二、Shuffle 优化

Shuffle 是性能瓶颈高发区。优化手段：① 减少 Shuffle 次数，用 Broadcast Join 代替 Shuffle Join（小表广播）；② 调整分区数（spark.sql.shuffle.partitions）；③ 开启 Shuffle 压缩；④ 用 SortMergeJoin 时保证大表排序有序；⑤ 避免数据倾斜（见下）。

三、数据倾斜解决

倾斜表现为部分 Task 长时间运行。常见方案：① 定位倾斜 Key，过滤后单独处理；② 加盐（随机前缀）打散热点 Key，再二次聚合；③ 提高倾斜 Task 的并行度（Adaptive Query Execution 自动优化）；④ 小表广播消除 Join 倾斜；⑤ 两阶段聚合。

四、实践建议

用 Spark UI 观察 Stage 耗时、Task 数据量、GC 时间；开启 Dynamic Allocation 动态分配资源；对大表做分区/分桶裁剪；用 Parquet + 列式压缩（如 ZSTD）减少 IO；定期清理小文件，保持文件数在合理范围。
