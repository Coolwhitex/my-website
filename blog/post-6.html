SQL 优化实战笔记

一、读懂执行计划

优化 SQL 的第一步是看执行计划（EXPLAIN）。关注三个点：① 访问方式（全表扫描还是索引/分区裁剪）；② Join 方式（Nested Loop 还是 Hash Join）与驱动表；③ 扫描行数估算与实际是否一致。计划暴露的问题往往比直觉更准确。

二、常见优化手段

① 只查需要的字段，避免 SELECT *；② 用 WHERE 条件前置过滤，减少中间结果；③ 分区表务必带分区条件，走分区裁剪；④ 大表关联用子查询先聚合再关联；⑤ 避免在索引列上做函数运算和隐式类型转换；⑥ 用 EXISTS 替代 IN（大数据量场景）。

三、百万级数据提速案例

某报表查询 5 分钟超时。排查发现：未带分区条件导致全表扫描，且两张大表直接关联。优化：① 增加分区过滤条件；② 将大表拆分为预聚合中间表；③ Join 前先按维度过滤；④ 结果缓存。优化后查询 3 秒内返回，提速约 100 倍。

四、规范化与习惯

SQL 不只是写对，还要写好：统一缩进与大小写；复杂逻辑用 CTE 拆解，逐段可读；加注释说明口径与来源；上线前做数据量级评估，防慢查询拖垮集群；建立慢查询监控，定期治理 TOP N 慢 SQL。
