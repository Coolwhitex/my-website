Flink 实时数仓实战

一、实时数仓的定位

离线数仓 T+1 的时效已无法满足实时运营需求。实时数仓在保留离线数仓分层思想的同时，把时效压缩到秒级。典型的链路是：业务日志 → Kafka → Flink 清洗计算 → 结果存储（ClickHouse/Redis）→ 服务层。

二、Flink 的核心概念

Flink 是流式处理引擎，核心抽象是 DataStream 与 Table API。开发时推荐优先使用 Flink SQL，可读性强、易于维护；复杂场景（自定义窗口、状态计算）再下沉到 DataStream API。注意区分事件时间与处理时间，业务统计通常用事件时间。

三、Exactly-Once 语义

通过 Checkpoint + Kafka 两阶段提交实现端到端精确一次。要点：合理设置 Checkpoint 间隔（如 60s），避免频繁快照影响吞吐；使用 Kafka 事务写入，保证下游一致性；监控反压和背压，及时扩容或优化算子并行度。

四、性能调优经验

① 合理设置并行度，与 Kafka 分区数对齐；② 用 RocksDB 状态后端处理大状态；③ 避免热点 Key，必要时加盐再聚合；④ 开启 Watermark 对齐与空闲源处理；⑤ 做好反压监控，backpressure 出现及时定位瓶颈算子。
